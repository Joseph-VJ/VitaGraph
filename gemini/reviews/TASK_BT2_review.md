## The defect to fix (Part 0 of B8, in `Graph3D.tsx`)
In `Graph3D.tsx` the `Controls` component creates the `OrbitControls` inside an effect whose dependency list contains `onPause` and `onResume`. The parent (`Scene`) passes `triggerPause` and `scheduleResume`, which are plain functions declared in the component body, so they are **new functions on every render of `Scene`**. `Scene` re-renders every time `hoveredIdx` changes, that is, every time the pointer enters or leaves a node. Each time, React runs the effect cleanup (`controls.dispose()`, listeners removed) and builds a new `OrbitControls`. Consequences: a drag that is in progress can be cut off when the pointer crosses a node, damping momentum is lost, the "end" event may never arrive so auto-rotation can stay paused, and OrbitControls is created and destroyed many times (the plan's rule 9 asks for creation once). Nothing mounts `Graph3D` yet, so it is only visible in the browser after B8; that is why it must be fixed and PROVEN in B8.
