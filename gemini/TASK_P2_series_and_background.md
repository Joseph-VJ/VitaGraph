## PART 1: the series endpoint (backend, do this first)
`GET /api/graph/{user_id}/series` returns, for the whole persona, every test's values across reports with printed ranges. The contract (P1 builds against it exactly):
```
{ "reports": [ { "report_id": str, "filename": str, "date": str|null, "date_iso": str|null, "order": int } ],
  "tests":   [ { "node_id": "test_Hemoglobin", "name": str, "unit": str, "category": str,
                 "points": [ { "report_id": str, "order": int, "date": str|null, "value": number,
                               "flag": "NORMAL"|"HIGH"|"LOW"|"CRITICAL"|"ABNORMAL",
                               "range_text": str|null, "range_low": number|null, "range_high": number|null,
                               "page_number": int, "chunk_id": str|null, "char_start": int|null, "char_end": int|null } ] } ] }
```
Rules:
- `reports`: all of the persona's reports in chronological order using `_date_key` (dated first in time order, undated LAST; ties by upload time); `order` = index 0..n-1; `date` is the printed text (e.g. `15 January 2025`) or null; `date_iso` is `YYYY-MM-DD` when parseable, else null (derive it from `_date_key`'s second element).
- `tests`: one entry per test name found by `measurement_service.list_report_measurements` over all reports (case-insensitive merge of names; `node_id` = `"test_" + name.replace(" ", "_")` using the FIRST spelling seen, which is what `app/graph/builder.py` builds; verify against the real graph in a test); `points` chronological by report `order`, at most one per report (the extractor already gives the first occurrence per report); sort `tests` by name.
- Ranges: `range_text` from the extractor's `reference_range`, else read from the page text with `_range_from_text(page_text, char_end)` (the extractor misses ranges that sit on their own line, e.g. the June sample report's Hemoglobin: `Reference range: 12.0 - 15.5 g/dL` on the next line); `range_low/high` from `measurement_service.parse_range`. A value without a range has all three null (NEVER invent a range). `flag` as the extractor gives it (NORMAL when none printed).
- Performance: `list_report_measurements` re-runs the extractor; cache its result per `report_id` in a module-level dict inside `series_service.py` (reports are immutable per id; also drop the entry for a report id that no longer exists when you rebuild). The 50-report demo persona must answer in a reasonable time (state the measured seconds cold and warm in your summary).
- Route in `app/routes/graph.py`: `@router.get("/{user_id}/series", response_model=SeriesOut)`: `user_service.user_exists(user_id)` (404 for an unknown persona), then call the service in `run_in_threadpool`. A persona with no reports returns `{"reports": [], "tests": []}`. No AI, nothing leaves the machine.
- Tests (new file, offline, fast): (a) two sample PDFs (`synthetic_panel_2025-01-15.pdf`, `synthetic_panel_2025-06-20.pdf`): reports in order Jan then Jun, Hemoglobin points 13.8 then 14.1 with `range_text` `12.0 - 15.5 g/dL` for BOTH (the June one comes from the text); (b) the scanned sample (`VitaGraph-Report4-Scanned-OCR-Test-2024-12-01.pdf`) is undated and comes LAST; (c) a value without a printed range has null range fields; (d) `node_id` of every test equals the id of a `test` node in `GET /api/graph/{uid}` (use `TestClient`); (e) another persona's data never appears; (f) unknown user 404; empty persona returns empty lists; (g) the cache returns the same content on a second call; (h) after `UPDATE reports SET report_date = ...` to `02 October 2025` and `20 June 2025` the order is June then October.
