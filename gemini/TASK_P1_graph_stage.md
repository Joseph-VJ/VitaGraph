## The data (real, replaces the preview's sample)
- **Nodes and edges**: from `GET /api/graph/{user_id}` through the existing `processGraphData` (chunk nodes hidden, top 120 by betweenness, `mapNodeKind`: person, report, section (= section, category and date nodes), bio (= test), meas (= measurement), unc (= uncertainty)). Keep those kinds and the preview's shapes/colours for them. The positions from `layout3D` are NOT used; your own layouts replace them.
- **Series (new endpoint, built by P2 in parallel)**: `GET /api/graph/{user_id}/series`. Contract (build `graphApi.series(userId)` and these types against it):
```
{ "reports": [ { "report_id": str, "filename": str, "date": str|null, "date_iso": str|null, "order": int } ],      // chronological, undated LAST, order = 0..n-1
  "tests":   [ { "node_id": "test_Hemoglobin", "name": str, "unit": str, "category": str,
                 "points": [ { "report_id": str, "order": int, "date": str|null, "value": number,
                               "flag": "NORMAL"|"HIGH"|"LOW"|"CRITICAL"|"ABNORMAL",
                               "range_text": str|null, "range_low": number|null, "range_high": number|null,
                               "page_number": int, "chunk_id": str|null, "char_start": int|null, "char_end": int|null } ] } ] }  // points chronological
```
  `node_id` equals the graph node id of the test (`test_` + name with spaces replaced by `_`). Use it for: the biomarker dossier (big latest value, change since the first reading, flag words, trend chart with the printed-range band), "What changed", the time machine, the Timeline layout (rows = tests, columns = reports) and the report order of every node (a measurement or uncertainty node belongs to the report order of its report; a test/section/category/date node appears at the first order where any of its neighbours' reports appears; the person node is order 0). If the endpoint is not there yet when you start (HTTP 404), build everything first and, until it exists, develop against a small typed fixture function used ONLY when the request fails with 404 in `import.meta.env.DEV`; at the end of Part 6 check again, and if it still 404s say so in the summary (the reviewer will integrate). Remove the fixture before you finish if the endpoint exists.
- **Report count is not 3.** Real personas have 1 to 50 reports. Everything the preview hard-codes for three dates must be generic: the time machine slider is `0..(reports-1)*100`; the Timeline layout column spacing is `min(0.5, 1.6/(reports-1))` and its date ticks thin out so they never overlap; the intro counters use the real counts; "Jan 2025 / Jun 2025 / Oct 2025" labels come from `lib/reportLabels.ts`; an undated report is labelled "Undated" and is shown last (never called the latest or oldest).
- **Ranges and flags**: only what the series says. A value without `range_text` is never described as inside or outside a range; a flag other than NORMAL is shown as "marked high/low" (▲/▼ words, as in the preview).
- **Groups for the Timeline lanes** = the test's `category`, in order of first appearance; lane spacing `min(0.12, 0.6/groups)`.
- **Evidence ("what the last answer cited")**: `readLastAnswer(userId)` gives `chunkIds`; the cited nodes are the shown nodes that are raw neighbours of those `chunk_<id>` nodes (test, measurement, section, report), numbered 1..n (at most 9), shown with the red numbered squares as in the preview. With no last answer the button is disabled and its text says "No answer to show yet. Ask the AI Agent first."
- **Subgraph list**: the real page has a "Subgraph" list (communities, from `processed.focuses`) that dims other nodes. The preview panel has no such list, but the owner's real app uses it, so KEEP it as the FIRST section of the right panel ("Subgraph", same rows as today), driving a `focusIds` dim in your engine.
